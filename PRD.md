# ЕГЭ Трекер — требования к продукту (PRD)

**Статус:** согласованная концепция, версия 1.0  
**Назначение:** личный инструмент ручного учёта решений и оценки подготовки к ЕГЭ.

## 1. Цель и границы

Пользователь решает задачи самостоятельно в любых внешних источниках, а в трекере записывает результаты. Приложение помогает увидеть динамику, определить слабые номера и понять, что пора повторить. Трекер **не содержит каталога условий ЕГЭ**, не загружает задачи из сторонних сервисов и не проверяет реальные решения автоматически.

Три предмета: **математика (профильная), русский язык, информатика**. Каждый содержит нумерованный список заданий с редактируемыми названиями. Начальный каталог номеров и названий должен поставляться как редактируемые локальные данные; конкретные актуальные формулировки нельзя выдумывать. Допустим нейтральный начальный набор номеров с названиями «Задание №N», пока не предоставлен утверждённый перечень.

## 2. Структура информации

`Предмет → Номер задания → (необязательная подтема) → Записи решений`.

- Решение обязательно принадлежит номеру задания; подтема может отсутствовать.
- Пользователь может создавать, переименовывать и удалять подтемы. При удалении подтемы записи остаются у номера без подтемы (с подтверждением).
- Можно добавлять решения без подтемы даже при наличии подтем.
- Статистика номера учитывает все его решения, независимо от подтемы; статистика подтемы — только связанные с ней.
- Название номера редактируется; идентификатор номера в рамках предмета уникален.

## 3. Основной сценарий: запись решения

На экране номера кнопка «Добавить решение» открывает компактную форму.

**Обязательное поле:** результат «Правильно» или «Неправильно». Дата/время по умолчанию — текущее локальное время; их можно изменить для внесения старых записей.

**Необязательные поля:** подтема, текст условия/описания, скриншот задания, мой ответ, правильный ответ, комментарий.

- Быстрый сценарий: выбрать результат и сохранить за 2–3 действия.
- Расширенная форма открывается по запросу; необязательные поля не блокируют сохранение.
- Если заполнены оба ответа, система может **предложить** результат по безопасному нормализованному сравнению текста (например, убрать пробелы по краям). Результат выставляется автоматически **только при однозначно сопоставимых ответах**, пользователь видит его и может изменить до сохранения. Никакой математической эквивалентности, проверки программного кода, семантической оценки или догадки о правильности.
- Если ответы нельзя достоверно сравнить, пользователь выбирает результат вручную. При отсутствии обязательного результата сохранение запрещено.
- Результат сохраняется и при наличии подробностей; редактирование ответов предлагает пересчитать результат, но не изменяет его скрытно.
- Поддержать добавление пачки результатов: N правильных и M неправильных без подробностей; создаются отдельные записи с общим временем/порядком, которые можно редактировать отдельно. N и M — целые неотрицательные, N+M > 0, разумный предел за одну операцию (например, 100).
- Просмотр истории в обратном хронологическом порядке; редактирование, удаление с подтверждением, просмотр скриншота.

## 4. Оценка подготовки

Разделять **взвешенное качество решений**, **объём практики** и **давность последней практики**. История хранится полностью, свежие решения влияют сильнее старых. Не сводить «хорошо освоено, но пора повторить» к статусу «плохо знает».

На уровне номера и подтемы показывать:
- количество всех решений, правильных и неправильных;
- общую точность (правильных / всего);
- взвешенную точность по времени решений;
- показатель уверенности с учётом объёма практики;
- дату последнего решения и прошедшее время;
- основной уровень освоения: «Не изучено», «Слабая подготовка», «Нужна практика», «Хорошо», «Отлично»;
- отдельную метку «Пора повторить» при наступлении срока.

Пороговые значения и формула версии 1 описаны в `ARCHITECTURE.md`. Это **эвристика**, а не научно подтверждённая оценка знаний или прогноз балла ЕГЭ.

## 5. Экраны

### Главная
- Три заметные карточки предметов, ведущие к спискам номеров.
- Сводка по всем предметам: объём практики, общая точность, количество номеров к повторению, недавняя активность.
- Блок «Что повторить» с быстрыми переходами.
- Не показывать общий «процент освоения» без понятного определения и подписи.

### Предмет
- Список номеров с названием, количеством решений, взвешенной точностью, уровнем освоения, датой практики и меткой повторения.
- Поиск по номеру/названию; фильтры «Все», «Не изучено», «Нужна практика», «Пора повторить»; сортировка по номеру и приоритету.

### Номер задания
- Показатели, уровень и срок повторения.
- Список подтем и их собственные показатели; решения без подтемы доступны отдельно.
- Хронология записей, подробный просмотр, добавление и изменение решений.
- Быстрый и расширенный ввод; пакетный ввод.

### Повторить
- Общая очередь номеров и, при наличии, подтем, отсортированная по срочности и слабым результатам.
- Объяснение причины рекомендации («давно не практиковался», «низкая точность», «мало решений»).
- Кнопка перехода к нужному номеру; без встроенного банка задач.

### Статистика
- Правильные/неправильные решения по дням за выбранный период; фильтр предмета.
- Динамика объёма практики и точности, понятные подписи и пустые состояния.
- Никаких фиктивных прогнозов тестового балла.

### Настройки и данные
- Экспорт всей информации в JSON, импорт с проверкой версии и предпросмотром состава.
- При импорте в первой версии — **полная замена** локальных данных после явного подтверждения и рекомендации сделать резервную копию. Не обещать объединение данных.
- Скриншоты входят в экспорт; показать предупреждение о потенциально большом размере файла.
- Возможность сброса данных только с подтверждением.

## 6. Визуальный стиль

Современный минималистичный академический интерфейс с ассоциациями с ЕГЭ: белый/очень светлый фон, синие акценты, тёмный текст, небольшие зелёные/янтарные/красные статусы. Рукописный характер **только у логотипа/названия**, остальной текст — высокочитаемый гротеск. Не копировать чужие логотипы и фирменную графику. Адаптивная сетка: смартфон — одна колонка, компьютер — расширенные карточки и таблицы. Контраст, управление с клавиатуры, текстовые подписи к цветовым статусам, доступные диалоги и формы обязательны.

## 7. Технические продуктовые ограничения

- Данные сохраняются **только локально в браузере**; на разных устройствах они независимы.
- Перенос между устройствами — ручной экспорт и импорт JSON.
- Приложение должно работать без сети после первоначального получения необходимых ресурсов, в рамках возможностей браузера и PWA.
- Скриншоты хранятся локально в виде Blob; JSON-резервная копия кодирует их в переносимом виде.
- Никаких учётных записей, серверной части и внешних API для основных функций.

## 8. За пределами первой версии

Агрегация заданий со сторонних сайтов; встроенное решение задач; автоматическая оценка сложных ответов; прогноз тестовых баллов; совместные аккаунты; синхронизация; полноценный календарь; геймификация. Добавлять только после отдельного согласования.

## 9. Критерии приёмки

1. Можно открыть каждый из трёх предметов и номер, создать подтему и запись без подтемы.
2. Можно сохранить решение с одним обязательным результатом; все дополнительные поля необязательны.
3. Можно добавить описание, ответы, комментарий и скриншот; всё сохраняется после перезагрузки страницы.
4. Можно просмотреть, изменить и удалить запись; статистика пересчитывается.
5. Старые результаты имеют меньший вес, чем новые; метка повторения работает независимо от уровня освоения.
6. Работают очередь повторения, фильтры и статистика.
7. Экспорт и импорт восстанавливают предметы, номера, подтемы, историю и изображения без потерь.
8. Интерфейс удобен на узком экране и на компьютере, доступен с клавиатуры.
9. Основные функции работают без сети при доступности ранее загруженного приложения.
