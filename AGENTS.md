# AGENTS.md — инструкции для Codex

## Цель

Разработать личный ЕГЭ-трекер строго по комплекту документов:
1. `PRD.md` — функции и критерии приёмки;
2. `ARCHITECTURE.md` — стек, слои и формула оценки;
3. `DATABASE.md` — сущности, ограничения и резервные копии;
4. `TASKS.md` — последовательность реализации.

При конфликте не угадывать намерение: сообщить о противоречии и предложить минимальное исправление. Требования пользователя приоритетнее необязательных идей.

## Неизменяемые ограничения

- Стек: React, TypeScript, Vite, Tailwind CSS, IndexedDB + Dexie.js, PWA.
- Только локальные данные; **никакого backend**, авторизации, внешней базы и обязательных API.
- Три предмета: профильная математика, русский язык, информатика.
- Структура: предмет → номер → необязательная подтема → отдельные решения.
- Единственное обязательное пользовательское поле решения — правильность. Подробности необязательны.
- Сохранять полную историю и скриншоты; экспорт/импорт JSON обязателен.
- Отдельно показывать освоение и необходимость повторения.
- Не добавлять каталог задач, автоматическую проверку сложных ответов или прогноз ЕГЭ без согласования.
- Не добавлять серверную инфраструктуру без отдельного разрешения.

## Инженерные правила

- TypeScript strict; избегать `any` без веской причины.
- Логику расчётов держать в чистых функциях доменного слоя.
- Компоненты UI не должны содержать SQL-подобную логику выборок или формулу оценки.
- Проверять внешние входы: JSON-файлы, пользовательский текст, изображения.
- Все составные операции с данными выполнять транзакционно, где это необходимо.
- Не терять историю при удалении подтемы; не оставлять осиротевшие вложения.
- Для результата, предлагаемого по тексту ответов, не делать неявных математических предположений.
- Использовать семантические элементы, доступные подписи, фокус и клавиатурную навигацию.
- Не включать фиктивную аналитику в рабочие экраны; показывать честные пустые состояния.
- При необходимости новых зависимостей объяснять их назначение.

## Порядок действий

1. Прочитать все четыре документа до начала существенных изменений.
2. Выполнять задачи в порядке `TASKS.md`.
3. После каждой порции изменений проверять типы, тесты и работоспособность затронутых сценариев.
4. Кратко сообщать, что сделано, какие проверки выполнены и какие ограничения остались.
5. Не отмечать задачу выполненной без проверяемого результата.

## Особо важные тесты

- Новые правильные решения влияют сильнее старых ошибок.
- Давность последней практики включает «Пора повторить», не подменяя уровень знаний.
- Решения без подтемы учитываются в номере; удаление подтемы сохраняет решения.
- Скриншоты переживают обновление страницы и экспорт/импорт.
- Неверный импорт не повреждает существующие данные.
- Быстрый ввод возможен без заполнения необязательных полей.
