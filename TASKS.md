# ЕГЭ Трекер — план реализации для Codex

Работать последовательно. После каждого этапа проверять сборку, типы и соответствующие тесты. Не переходить к следующему этапу с известными критическими ошибками. Детали требований — `PRD.md`, архитектуры — `ARCHITECTURE.md`, данных — `DATABASE.md`.

## Этап 1. Каркас и дизайн-система

- [x] Создать приложение React + TypeScript + Vite с Tailwind CSS и строгой типизацией.
- [x] Настроить структуру модулей, маршрутизацию, линтер и тестовый инструментарий.
- [x] Сделать адаптивную навигацию: Главная, Предметы, Повторить, Статистика, Настройки.
- [x] Реализовать базовые компоненты: кнопки, карточки, бейджи, диалоги, формы, пустые состояния.
- [x] Оформить минималистичную палитру и рукописный акцент логотипа без ущерба читаемости.

**Готово, когда:** навигация работает на мобильной и широкой ширине, базовые компоненты доступны с клавиатуры.

## Этап 2. Модель и локальное хранение

- [x] Описать типы Subject, Exercise, Subtopic, Attempt, Attachment.
- [x] Реализовать Dexie-схему, индексы и репозитории.
- [x] Заполнить три предмета и редактируемый каталог номеров с нейтральными названиями; не выдумывать официальные названия.
- [x] Реализовать CRUD подтем, включая отвязку решений при удалении.
- [x] Реализовать транзакции, проверку ссылок и операции над вложениями.
- [x] Добавить интеграционные тесты базы.

**Готово, когда:** данные переживают обновление страницы; нет потерянных ссылок.

## Этап 3. Ввод и история решений

- [x] Создать экран номера и историю решений.
- [x] Добавить быстрый ввод «Правильно/Неправильно».
- [x] Добавить раскрываемые необязательные поля, дату решения и выбор подтемы.
- [x] Добавить скриншот с предпросмотром, ограничением MIME/размера и хранением Blob.
- [x] Реализовать осторожное предложение результата при сопоставимых ответах с ручным подтверждением/переопределением.
- [x] Реализовать редактирование и удаление решений.
- [x] Реализовать пакетный ввод N правильных и M неправильных.

**Готово, когда:** все варианты записей сохраняются и редактируются, обязательным остаётся только результат.

## Этап 4. Алгоритм и очередь повторения

- [x] Реализовать чистые функции взвешенной точности, уверенности, уровня и интервала повторения строго по `ARCHITECTURE.md`.
- [x] Разделить уровень освоения и метку «Пора повторить».
- [x] Посчитать агрегаты по номеру и подтеме.
- [x] Создать очередь повторения с объяснением причин и сортировкой по приоритету.
- [x] Покрыть тестами пустую историю, разные даты, одинаковые даты, ввод задним числом, правки и граничные значения.

**Готово, когда:** свежие решения имеют больший вес, а давность не уничтожает показатель освоения.

## Этап 5. Основные экраны и аналитика

- [x] Главная: три предмета, сводка, ближайшие повторения.
- [x] Предмет: список номеров, поиск, фильтры и сортировка.
- [x] Номер: показатели, подтемы, история и формы.
- [x] Статистика: правильные/неправильные по дням, фильтр периода и предмета.
- [x] Убедиться, что нет вводящих в заблуждение «прогнозов балла» и неопределённых процентов.

**Готово, когда:** весь пользовательский сценарий выполняется без перехода к техническим инструментам.

## Этап 6. Резервные копии

- [x] Реализовать полный экспорт JSON с `schemaVersion`, датой, сущностями и изображениями base64.
- [x] Реализовать валидацию JSON, проверку ссылок, типов, размера и версии.
- [x] Показать предпросмотр импорта и подтверждение полной замены данных.
- [x] Выполнить атомарную замену; при ошибке сохранить прежнюю базу.
- [x] Проверить round-trip экспорт→импорт, в том числе изображения и записи без подтем.
- [x] Реализовать безопасный сброс данных с подтверждением.

**Готово, когда:** резервная копия восстанавливает весь пользовательский контент без потерь.

## Этап 7. PWA, адаптивность и итоговая проверка

- [x] Добавить PWA-манифест, иконки и кеш статических ресурсов.
- [x] Проверить доступность ранее загруженного интерфейса без сети.
- [x] Проверить экраны шириной от ~320 px, навигацию с клавиатуры, контраст и фокус.
- [x] Запустить unit, integration и E2E тесты, исправить выявленные ошибки.
- [x] Проверить отсутствие обязательных сетевых запросов для основных функций.
- [x] Подготовить краткую инструкцию пользователя: добавление решений, подтемы, резервная копия.

**Готово, когда:** выполнены критерии приёмки из `PRD.md`.

## Принцип работы

Реализовывать небольшими проверяемыми порциями. Не добавлять неутверждённые крупные функции. При неоднозначности требований выбирать простейшее безопасное поведение и фиксировать допущение; существенные изменения согласовывать с пользователем.
