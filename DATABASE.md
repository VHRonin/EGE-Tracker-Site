# ЕГЭ Трекер — локальная модель данных

## 1. Источник истины

**IndexedDB через Dexie.js.** Данные каждого браузерного профиля независимы. Полный перенос возможен через JSON. Все идентификаторы строковые UUID, даты хранятся в ISO 8601 UTC.

## 2. Сущности

### `subjects`

| Поле | Тип | Правила |
|---|---|---|
| `id` | string | PK; стабильные ID для трёх предметов |
| `code` | `'math' \| 'russian' \| 'informatics'` | Уникальное значение |
| `title` | string | Отображаемое имя |
| `sortOrder` | number | Порядок отображения |

### `exercises` — номера заданий

| Поле | Тип | Правила |
|---|---|---|
| `id` | string | PK |
| `subjectId` | string | Ссылка на `subjects.id` |
| `number` | number | Положительное целое; уникально в рамках предмета |
| `title` | string | Редактируемое название |
| `createdAt`, `updatedAt` | string | ISO UTC |

### `subtopics`

| Поле | Тип | Правила |
|---|---|---|
| `id` | string | PK |
| `exerciseId` | string | Ссылка на `exercises.id` |
| `title` | string | Непустое название |
| `sortOrder` | number | Порядок |
| `createdAt`, `updatedAt` | string | ISO UTC |

### `attempts` — отдельные решения

| Поле | Тип | Правила |
|---|---|---|
| `id` | string | PK |
| `exerciseId` | string | Обязательно |
| `subtopicId` | string \| null | Необязательно; подтема должна принадлежать тому же номеру |
| `isCorrect` | boolean | Обязательно; единственное обязательное пользовательское поле |
| `solvedAt` | string | Время решения; по умолчанию текущее |
| `description` | string \| null | Текст условия |
| `myAnswer` | string \| null | Ответ пользователя |
| `correctAnswer` | string \| null | Эталонный ответ |
| `comment` | string \| null | Комментарий |
| `createdAt`, `updatedAt` | string | ISO UTC |

### `attachments` — скриншоты

| Поле | Тип | Правила |
|---|---|---|
| `id` | string | PK |
| `attemptId` | string | Ссылка на `attempts.id` |
| `filename` | string | Исходное имя |
| `mimeType` | string | Разрешённый тип изображения, например image/png, image/jpeg, image/webp |
| `size` | number | Размер в байтах |
| `blob` | Blob | Бинарные данные, **не** data URL внутри IndexedDB |
| `createdAt` | string | ISO UTC |

В первой версии достаточно одного скриншота на запись; модель допускает расширение до нескольких. Проверять MIME и размер до сохранения (например, до 10 МБ на файл), при необходимости сжимать изображение с согласия пользователя.

## 3. Индексы Dexie (пример)

```ts
// Версия схемы 1; пример описания индексов Dexie.
db.version(1).stores({
  subjects: 'id, &code, sortOrder',
  exercises: 'id, subjectId, &[subjectId+number]',
  subtopics: 'id, exerciseId, [exerciseId+sortOrder]',
  attempts: 'id, exerciseId, subtopicId, solvedAt, [exerciseId+solvedAt], [subtopicId+solvedAt]',
  attachments: 'id, attemptId',
});
```

Не использовать `null` в составных индексах, которые должны находить записи без подтемы: для них запрос по `exerciseId` и фильтрация `subtopicId === null` либо отдельное поле-маркер.

## 4. Инварианты и каскадные операции

- Нельзя создать попытку с отсутствующим номером.
- Если `subtopicId` задан, он должен принадлежать `exerciseId` попытки.
- При удалении подтемы её попытки сохраняются и получают `subtopicId = null` в одной транзакции.
- При удалении попытки удаляются её вложения в одной транзакции.
- Удаление номера с историей требует подтверждения и каскадного удаления его подтем, попыток и вложений.
- В первой версии предметы фиксированы; удаление предметов не предусмотрено.
- При массовом вводе создаётся по одной записи на результат, чтобы сохранялась честная история.
- Оценки, проценты и даты последней практики **вычисляются из attempts**, а не дублируются в таблицах.

## 5. Формат JSON-резервной копии

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-10-15T12:00:00.000Z",
  "subjects": [{"id": "math", "code": "math", "title": "Математика (профиль)", "sortOrder": 0}],
  "exercises": [{"id": "ex-1", "subjectId": "math", "number": 1, "title": "Задание №1", "createdAt": "2026-10-15T12:00:00.000Z", "updatedAt": "2026-10-15T12:00:00.000Z"}],
  "subtopics": [],
  "attempts": [{"id": "a-1", "exerciseId": "ex-1", "subtopicId": null, "isCorrect": true, "solvedAt": "2026-10-15T12:00:00.000Z", "description": null, "myAnswer": null, "correctAnswer": null, "comment": null, "createdAt": "2026-10-15T12:00:00.000Z", "updatedAt": "2026-10-15T12:00:00.000Z"}],
  "attachments": []
}
```

В реальном экспорте **всегда** присутствуют все три предмета и весь каталог. Пример выше намеренно сокращён и показывает структуру, а не готовую резервную копию.

Элемент `attachments` в JSON содержит метаданные и `base64` вместо `blob`. Импорт восстанавливает Blob, проверяет размер, MIME, ссылочную целостность и версию. Неизвестная версия — понятная ошибка без изменения базы. Экспорт/импорт включают полную историю и изображения; данные могут занимать много места.

## 6. Версионирование

Версии схемы Dexie и версии JSON независимы. Любое изменение требует миграции локальных записей и отдельной проверки совместимости резервных копий. Тестировать обновление с предыдущей версии и откат импорта при ошибке.
